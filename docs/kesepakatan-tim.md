## 2. Komunikasi

## 3. Aturan Git
- Tidak melakukan push langsung ke `main`; seluruh perubahan melalui branch dan Pull Request.
- Format nama branch: `fitur-...`, `perbaikan-...`, atau `docs-...`.
- Setiap PR ditinjau minimal 1 anggota lain sebelum di-merge (atau ditinjau mandiri secara menyeluruh bila solo).
- Pesan commit ditulis dalam bahasa Indonesia yang menjelaskan isi perubahan.

## 4. Aturan Penggunaan AI
- Setiap penggunaan AI dicatat di bagian Penggunaan AI pada PR dan di `jurnal-vibe-coding.md`.
- Dilarang menempelkan kata sandi, token, kunci akses, atau data pribadi klien ke prompt AI.
- Seluruh kode hasil AI wajib dibaca, diuji, dan ditinjau sebelum di-commit.

## 5. Definition of Done
Sebuah fitur dianggap selesai apabila:
1. Memenuhi seluruh kriteria penerimaan yang ditetapkan.
2. Sudah dijalankan dan diuji tanpa galat (termasuk uji keamanan masukan).
3. Pull Request telah ditinjau dan disetujui tanpa konflik.
4. Jurnal Vibe Coding sudah diperbarui.

## 6. Jika Ada Masalah
- **Anggota tidak aktif:** Dihubungi secara personal terlebih dahulu; jika tidak ada respons lebih dari 2×24 jam, didiskusikan bersama tim dan dilaporkan ke dosen pengampu.
- **Perbedaan pendapat:** Diselesaikan melalui diskusi berbasis data/spesifikasi klien; bila buntu, diputuskan melalui pemungutan suara mayoritas atau konsultasi dengan dosen.
