## 4.5 Rilis dan Dokumentasi

Pengemasan rilis perdana perangkat lunak mengikuti standar *Semantic Versioning 2.0.0* dengan nomor versi **`v1.0.0`** yang tercatat pada modul `versi.py` dan ditampilkan pada kaki setiap halaman antarmuka (`templates/base.html`). Setelah seluruh rangkaian pengujian otomatis lulus pada branch `main`, dibuat tag Git beranotasi `v1.0.0` pada commit merge `a410186` (diikuti pembaruan kelengkapan tangkapan layar manual pada commit `8902c5e`) serta dipublikasikan secara resmi melalui fitur **GitHub Releases** pada tautan `https://github.com/RanggaPratamaAditya/rpl-manajemen-keuangan/releases/tag/v1.0.0`.

| Artefak Rilis | Lokasi di Repositori | Ringkasan Isi dan Peran Operasional |
|---|---|---|
| Tag & GitHub Release | Tag `v1.0.0` (commit `a410186`) | Penanda resmi versi produksi pertama beserta catatan perubahan dan arsip kode sumber `.zip`/`.tar.gz`. |
| Catatan Perubahan | `CHANGELOG.md` | Merangkum seluruh fitur utama `v1.0.0` (autentikasi dua peran, CRUD transaksi & kategori, ekspor CSV, keamanan, dan cadangan). |
| Panduan Teknis | `README.md` | Memuat spesifikasi lingkungan, langkah instalasi `.venv`, konfigurasi variabel produksi Waitress, dan prosedur pemulihan data. |
| Manual Pengguna | `docs/manual-pengguna.md` | Panduan operasional non-teknis bagi Pemilik dan Kasir yang dilengkapi 5 tangkapan layar pada `docs/gambar/`. |
| Utilitas Cadangan | `cadangkan.py` | Skrip CLI untuk menyalin berkas basis data aktif ke folder `cadangan/` dengan penamaan stempel waktu otomatis. |

*Sumber data: `CHANGELOG.md`, `README.md`, `docs/manual-pengguna.md`, dan riwayat tag Git `v1.0.0`.*

Pada lingkungan produksi, aplikasi dijalankan menggunakan server WSGI **Waitress** (`waitress-serve --listen=127.0.0.1:8000 app:app`) dengan mengaktifkan empat variabel lingkungan wajib, yaitu `APP_ENV=production`, `SECRET_KEY` acak 64 karakter heksadesimal, `KEUANGAN_DB=keuangan-rilis.db`, serta `COOKIE_SECURE`. Pemisahan berkas basis data operasional dari basis data pengujian menjamin integritas data transaksi UMKM tetap aman saat pembaruan kode dilakukan. Untuk mitigasi kehilangan data akibat kerusakan perangkat, administrator menjalankan `python cadangkan.py` secara berkala guna menghasilkan salinan cadangan SQLite yang dapat dipulihkan dengan menyalin ulang berkas cadangan ke jalur `KEUANGAN_DB` saat server dihentikan sementara.

Kelayakan dokumentasi teknis diverifikasi melalui **uji orang asing** (*stranger test*), yakni meminta rekan mahasiswa memasang dan menjalankan aplikasi di direktori baru dengan `.venv` bersih hanya berbekal `README.md` tanpa bantuan lisan. Penguji berhasil menyelesaikan proses instalasi, pembuatan akun awal lewat `buat_pengguna.py`, hingga membuka halaman `/login`, dan temuan kecil terkait sintaks aktivasi PowerShell telah langsung diperbarui pada `README.md`. Secara jujur, rilis `v1.0.0` masih memiliki keterbatasan operasional berupa ketiadaan antarmuka web untuk manajemen akun pengguna (masih melalui CLI `buat_pengguna.py`), belum tersedianya fitur pencadangan terjadwal otomatis di latar belakang, serta belum adanya grafik analitik bulanan yang telah dijadwalkan untuk iterasi `v1.1.0`.
